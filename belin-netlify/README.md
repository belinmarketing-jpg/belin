# belin. — Netlify + Supabase

Адаптация сайта под Netlify без постоянно работающего Node.js-сервера. Главная страница, анимации, кейсы, отзывы, заявки, админка, загрузка изображений, редактирование настроек и политики.

## Перед публикацией (обязательно)

1. Создайте **новый** проект Supabase (либо используйте свой, если он предназначен для belin.). В SQL Editor выполните `supabase/schema.sql`.
2. В Supabase → Authentication → Users создайте администратора с email и паролем; скопируйте UUID пользователя. В SQL Editor выполните `insert into public.admin_users(user_id) values ('UUID');`. Саморегистрацию можно отключить в Auth → Providers.
3. В Supabase → Storage создайте **public bucket** `site-assets`. Не загружайте туда конфиденциальные документы. Для таблиц оставьте RLS включённым.
4. На Netlify: **Add new project → Import an existing project**, загрузите этот проект в GitHub/GitLab и подключите репозиторий. Папка публикации `public`, functions `netlify/functions` уже указаны в `netlify.toml`. Либо Netlify CLI `netlify deploy --build --prod` из корня проекта (после авторизации и привязки сайта). Обычный drag-and-drop папки `public` НЕ развернёт функции.
5. В Netlify → Project configuration → Environment variables добавьте **SUPABASE_URL**, **SUPABASE_ANON_KEY** (публичный publishable/anon), **SUPABASE_SERVICE_ROLE_KEY** (секретный service_role). Все значения берите в Supabase → Project Settings → API. **Секретный ключ никогда не вставляйте в JS, Git или публичные файлы.** Выполните новый deploy.
6. Откройте `https://ваш-сайт.netlify.app/admin` и войдите под созданным пользователем. Проверьте редактирование и публикацию кейсов.
7. Заполните политику обработки персональных данных с корректными сведениями об операторе. Только затем включите форму в админке. Проверьте тестовую заявку в разделе «Заявки».
8. Подключите `belin.su` через Netlify → Domain management, настройте DNS по инструкциям Netlify, дождитесь HTTPS.

## Локальный запуск

Node.js 20+. Установите зависимости `npm install`, создайте `.env` по примеру `.env.example`, запустите `npx netlify dev`. Функции используют переменные окружения из локального `.env` или настроек Netlify.

## Что работает

- Публичный контент читается через `GET /api/public`; политика через `/api/privacy`.
- Админ авторизуется Supabase Auth; каждый админ-запрос дополнительно проверяется по `admin_users` на сервере.
- Данные хранятся в PostgreSQL Supabase; изображения — в Storage.
- Заявки сохраняются только при включённой форме и заполненной политике, с honeypot и простым ограничением частоты по IP. Для серьёзной нагрузки дополнительно рекомендуются CAPTCHA/Turnstile и защита от DDoS.
- Адаптивная вёрстка, анимации и визуальный стиль перенесены из исходного проекта.

## Ограничения и честные замечания

- **Не является проверенным боевым развёртыванием:** в этой среде нет доступа к вашим Netlify/Supabase аккаунтам, DNS и ключам. Пройдите шаги выше и протестируйте сайт перед запуском.
- Уведомления о заявках по почте/Telegram не настроены: заявки доступны в админке. Для уведомлений понадобится интеграция почтового провайдера/бота.
- Показанные на концепте клиенты, метрики и отзывы не подтверждены и не добавлены как факты.
- Политика персональных данных должна быть проверена владельцем сайта с учётом применимого законодательства. При использовании зарубежной инфраструктуры проверьте требования к локализации персональных данных и трансграничной передаче, особенно для российских клиентов.
- Изображение логотипа из генератора — растровый референс; для типографического идеала потребуется векторная перерисовка.
- Не включайте форму до завершения юридической настройки. Обработка заявок требует продуманной политики хранения/удаления.

## Структура

`public/` — сайт и админка; `netlify/functions/api.mjs` — серверные API; `supabase/schema.sql` — таблицы и настройки; `netlify.toml` — публикация и маршрутизация.
