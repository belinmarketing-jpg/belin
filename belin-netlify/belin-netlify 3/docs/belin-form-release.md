# Заявки BELIN: подготовка без публикации основного сайта

## Архитектура

Рабочая форма для клиентов из России должна отправлять данные напрямую из браузера на российский хостинг. Netlify и Supabase не проксируют реальные обращения. Для существующего REG.RU «Хост-0» u3472710 подготовлен CGI-обработчик на Python 3 с SQLite (`server/intake.py`) и отдельный, закрытый просмотр заявок (`server/admin.py`). Возможность запуска CGI, версия SQLite, расположение сервера и резервных копий проверяются в панели до включения.

Для технической проверки Supabase приготовлена дополнительная миграция `20261112114950_studio_lead_consent.sql`: только фиксированные вымышленные данные, отдельная отметка is_test, атомарная запись и ограничитель. Она **ещё не применена к studio**. Начальную миграцию клиентской платформы повторно не выполнять.

## Установка на существующем хостинге

1. После входа в REG.RU проверить действующую услугу и возможность Python CGI. Не подключать платные опции или менять тариф без согласования. Не направлять основной belin.su на этот хостинг.
2. Подготовить отдельный поддомен, например forms.belin.su, и отдельный каталог. Перед сохранением DNS/созданием публичного адреса согласовать конкретную запись с владельцем. Включить HTTPS средствами существующего тарифа без платной покупки сертификата.
3. В публичном каталоге находятся только intake.py, admin.py и адаптированный .htaccess.example. Python-скриптам нужны права запуска. Конфигурация и leads.sqlite должны лежать вне любых публичных каталогов; путь передаётся BELIN_PRIVATE_DIR.
4. Создать приватный config.json на основе server/config.example.json. Не добавлять секрет throttleSalt в GitHub, чат или публичные файлы. Указать точные разрешённые origins. Хранилище и резервные копии — только в РФ, с ограниченным доступом.
5. Защитить admin.py авторизацией веб-сервера (пользователь и пароль создаются владельцем лично). Без REMOTE_USER скрипт возвращает 403. Открытый административный URL без защиты не использовать.
6. Заполнить проекты public/legal/privacy-draft.txt и consent-draft.txt: адрес оператора, сведения о российском обработчике, сроки хранения/резервных копий, порядок удаления. Пока это черновики, approved/hostingConfirmed/enabled остаются false.
7. После согласования документов и проверки размещения выставить флаги в приватном config.json. Настроить регулярное удаление по утверждённым срокам; текущий код не удаляет обращения автоматически. Не обещать автоматическую очистку в опубликованной политике до реализации и проверки.
8. Только в тестовом Netlify сначала задать BELIN_RU_LEADS_ORIGIN=https://forms.belin.su и BELIN_STUDIO_FORMS_ENABLED=true. Проверить запросы /documents и /leads, CORS, отказ без согласия, устаревшую версию и дубли, появление вымышленной заявки в российском закрытом интерфейсе. Содержимое заявок в Supabase не копируется.
9. После отдельного согласования выпуска перенести настройки на основной сайт и опубликовать PR. До этого основной сайт остаётся прежним.

## Ключи

- Раскрытые новые ключи: default и belin_test_netlify. Они ещё не отозваны.
- У основного belin.su в Netlify обнаружен legacy JWT-ключ; новое значение ему не назначалось. Значения не выводились в отчёт.
- Для тестового сайта подготовлено создание belin_preview_20261112; владелец должен завершить создание лично.
- После переноса нового ключа в секреты только Production-контекста отдельного тестового проекта проверить чтение каталога и авторизацию. Только затем согласовать конкретное удаление раскрытых ключей и проверить их отзыв. Не удалять legacy JWT-ключи или неустановленные зависимости.
- Не показывать поля секретов, .env или сырой снимок интерфейса: значения должны редактироваться без вывода в инструменты. Проверять сохранение через маскированное состояние либо переход на другую страницу после завершения запроса.

## Ограничения

Политика формы не решает автоматически вопросы российских учётных записей Supabase Auth, сброса пароля и трансграничной обработки: это отдельный аудит до коммерческого запуска кабинета. Resend не используется для отправки содержимого заявок. Уведомления на почту в подготовленном российском обработчике пока не включены; заявки просматриваются в его закрытом интерфейсе.

Правовая основа для согласования: статья 18 (локализация) и статья 9 (отдельное согласие) 152-ФЗ: https://mintrud.gov.ru/docs/laws/130. Тариф REG.RU и технологии: https://www.reg.ru/hosting/.
